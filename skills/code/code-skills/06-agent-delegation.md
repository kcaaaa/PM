# 子代理委派 Agent Delegation

> 当前项目适配：子代理委派必须绑定 `IMP-*` 实现包，且每个子代理任务都必须能追溯到具体的实现任务清单；子代理的规范审查应包含对 `Base/` 对象包链路的合规性检查；最终验证结果必须回写到 `TEST-*` 或对应实现记录中。

## 1. 核心原则

### 1.1 子代理驱动开发
- **每个任务使用新鲜子代理**：避免上下文污染，确保每个任务从干净状态开始
- **两阶段审查**：先规范合规性审查，再代码质量审查
- **持续执行**：任务之间不暂停检查，执行计划中的所有任务直到完成

### 1.2 模型选择策略
使用能够处理每个角色的最小能力模型，以节省成本并提高速度：

| 任务类型 | 推荐模型 | 适用场景 |
|---|---|---|
| 机械实现任务 | 快速、便宜的模型 | 独立函数、明确规范、1-2 个文件 |
| 集成和判断任务 | 标准模型 | 多文件协调、模式匹配、调试 |
| 架构、设计和审查任务 | 最强大的模型 | 方案设计、代码审查、架构决策 |

## 2. 使用时机判断

```
有实现计划？
    │
    ├─ 是 → 任务大多独立？
    │         │
    │         ├─ 是 → 在当前会话中执行？
    │         │         │
    │         │         ├─ 是 → 使用子代理驱动开发
    │         │         │
    │         │         └─ 否 → 使用执行计划（并行会话）
    │         │
    │         └─ 否（紧密耦合）→ 手动执行或先头脑风暴
    │
    └─ 否 → 手动执行或先头脑风暴
```

### 与执行计划（并行会话）对比

| 维度 | 子代理驱动开发 | 执行计划（并行会话） |
|---|---|---|
| 上下文 | 同一个会话 | 多个并行会话 |
| 任务隔离 | 每个任务新鲜子代理 | 会话间隔离 |
| 审查机制 | 两阶段审查内置 | 需要额外配置 |
| 迭代速度 | 更快（无需人工介入） | 可能需要协调 |

## 3. 流程规范

### 3.1 每个任务的执行流程

1. **分配实现子代理**
2. **子代理提问？**
   - 是：回答问题，提供上下文，重新分配
   - 否：继续实现
3. **子代理实现、测试、自我审查**
4. **分配规范审查子代理**
5. **规范审查通过？**
   - 否：实现子代理修复规范缺口，重新审查
   - 是：继续
6. **分配代码质量审查子代理**
7. **代码质量审查批准？**
   - 否：实现子代理修复质量问题，重新审查
   - 是：标记任务完成

### 3.2 完整工作流程

```
读取 IMP-* 任务清单，提取所有任务，创建 TodoWrite
    │
    ▼
[对每个任务重复以上流程]
    │
    ▼
所有任务完成后，分配最终代码审查子代理
    │
    ▼
验证结果回写到 Base/09-测试验收/TEST-*/测试记录.md
```

## 4. 代理状态处理

实现子代理报告四种状态之一，需要正确处理：

| 状态 | 处理方式 |
|---|---|
| **DONE** | 继续进行规范合规性审查 |
| **DONE_WITH_CONCERNS** | 先阅读疑虑。如果涉及正确性或范围，先解决再审查；如果只是观察，记录并继续审查 |
| **NEEDS_CONTEXT** | 提供缺失的上下文并重分配 |
| **BLOCKED** | 评估阻塞原因：1) 上下文问题 → 提供更多上下文；2) 需要更多推理 → 使用更强大模型；3) 任务太大 → 拆分；4) 计划有问题 → 升级给人类 |

**绝对不要**忽略升级或强制相同模型在不改变的情况下重试。

## 5. 红牌警告

| 禁止行为 | 原因 |
|---|---|
| 在未获得用户明确同意的情况下在主分支开始实现 | 违反变更管理规范 |
| 跳过审查（规范合规性或代码质量） | 无法保证代码质量 |
| 带着未修复的问题继续 | 会导致后续问题累积 |
| 并行分配多个实现子Agent（会冲突） | 会导致代码冲突 |
| 让子Agent读取计划文件（应提供完整文本） | 可能导致上下文不一致 |
| 跳过场景设置上下文 | 子Agent需要理解任务位置 |
| 忽略子Agent的问题 | 会导致实现偏差 |
| 在规范合规性通过之前开始代码质量审查 | 顺序错误 |
| 在任一审查有未解决问题时移动到下一个任务 | 会遗漏问题 |
| 让实现子Agent的自我审查替代实际审查 | 两者都需要 |

## 6. 项目适配约束

### 6.1 Base 链路约束
- 子代理委派必须绑定 `IMP-*` 实现包
- 每个子代理任务都必须能追溯到具体的实现任务清单
- 规范审查应包含对 `Base/` 对象包链路的合规性检查
- 最终验证结果必须回写到 `TEST-*` 或对应实现记录中

### 6.2 安全约束
- 子代理不得执行破坏性操作（删除、覆盖、推送），必须经由主代理确认
- 子代理的代码审查必须包含安全审查
- 涉及敏感数据或外部 API 的任务需要额外安全验证
