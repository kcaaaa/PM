## 1. 架构设计原则

### 1.1 SOLID 原则

| 原则 | 说明 |
|---|---|
| Single Responsibility | 单一职责：每个类只负责一个功能 |
| Open/Closed | 开闭原则：对扩展开放，对修改关闭 |
| Liskov Substitution | 里氏替换：子类可以替换父类 |
| Interface Segregation | 接口隔离：客户端不应依赖不需要的接口 |
| Dependency Inversion | 依赖倒置：依赖抽象而非具体实现 |

### 1.2 设计模式

| 模式 | 用途 | 示例 |
|---|---|---|
| Singleton | 确保类只有一个实例 | 数据库连接池 |
| Factory | 创建对象的接口 | 日志工厂 |
| Observer | 一对多依赖关系 | 事件系统 |
| Strategy | 算法封装 | 支付方式 |
| Decorator | 动态添加功能 | 权限装饰器 |

## 2. 系统架构模式

### 2.1 单体架构

```
┌───────────────────────────────────────┐
│           单体应用                     │
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐     │
│  │ API │ │ 业务 │ │ 数据 │ │ 视图 │     │
│  └─────┘ └─────┘ └─────┘ └─────┘     │
└───────────────────────────────────────┘
```

**适用场景**：中小型项目、快速迭代、团队规模小

**优点**：简单、开发效率高、部署方便

**缺点**：耦合度高、扩展性差、维护困难

### 2.2 微服务架构

```
┌─────────────────────────────────────────┐
│              API Gateway                │
├──────────┬──────────┬──────────┬───────┤
│  用户服务  │  订单服务  │  商品服务  │  支付服务  │
├──────────┼──────────┼──────────┼───────┤
│  数据库1   │  数据库2   │  数据库3   │  数据库4   │
└──────────┴──────────┴──────────┴───────┘
```

**适用场景**：大型项目、高并发、团队规模大

**优点**：解耦、独立部署、可扩展性强

**缺点**：复杂度高、运维成本高、分布式事务

### 2.3 分层架构

```
┌──────────┐
│  表现层   │
├──────────┤
│  业务层   │
├──────────┤
│  数据层   │
├──────────┤
│  持久层   │
└──────────┘
```

**适用场景**：大多数 Web 应用

**优点**：职责清晰、易于维护、便于测试

## 3. 前端架构

### 3.1 组件化架构

```
App/
├── components/     # 通用组件
│   ├── Button/
│   ├── Input/
│   └── Card/
├── features/       # 功能模块
│   ├── auth/
│   │   ├── login/
│   │   └── register/
│   └── dashboard/
├── pages/          # 页面
├── hooks/          # 自定义 Hooks
├── store/          # 状态管理
└── utils/          # 工具函数
```

### 3.2 状态管理方案

| 方案 | 适用场景 | 复杂度 |
|---|---|---|
| useState | 简单状态 | 低 |
| useContext | 全局状态（中小项目） | 中 |
| Zustand | 全局状态（推荐） | 中 |
| Redux Toolkit | 复杂全局状态 | 高 |

### 3.3 数据获取方案

```javascript
// TanStack Query (推荐)
import { useQuery } from '@tanstack/react-query';

const { data, isLoading, error } = useQuery({
  queryKey: ['users'],
  queryFn: fetchUsers
});
```

## 4. 后端架构

### 4.1 MVC 架构

```
┌─────────────┐
│   Router    │ 路由分发
├─────────────┤
│   Controller│ 请求处理
├─────────────┤
│   Service   │ 业务逻辑
├─────────────┤
│   Model     │ 数据模型
└─────────────┘
```

### 4.2 目录结构

```
src/
├── controllers/    # 控制器
├── services/       # 服务层
├── models/         # 数据模型
├── routes/         # 路由
├── middleware/     # 中间件
├── utils/          # 工具函数
├── config/         # 配置文件
└── app.js          # 入口文件
```

### 4.3 中间件设计

```javascript
// 认证中间件
const authenticate = (req, res, next) => {
  const token = req.headers.authorization;
  if (!token) return res.status(401).json({ message: 'Unauthorized' });
  // 验证 token...
  next();
};

// 日志中间件
const logger = (req, res, next) => {
  console.log(`${req.method} ${req.path}`);
  next();
};
```

## 5. 数据库架构

### 5.1 数据库选择

| 数据库 | 类型 | 适用场景 |
|---|---|---|
| PostgreSQL | 关系型 | 复杂查询、事务、数据一致性 |
| MySQL | 关系型 | 高并发、读写分离 |
| MongoDB | 文档型 | 非结构化数据、快速迭代 |
| Redis | 缓存 | 高性能读写、会话存储 |

### 5.2 数据库设计原则

- [ ] 遵循数据库范式（1NF、2NF、3NF）
- [ ] 合理设计主键和外键
- [ ] 创建合适的索引
- [ ] 考虑数据分区和分片
- [ ] 设计读写分离方案
