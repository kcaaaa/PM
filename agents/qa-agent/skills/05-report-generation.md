# 阶段5 · 报告生成技能

> 汇总前四个阶段的验证结果，生成结构化 QA 报告和明确的决策建议。

---

## 1. 职责

- 整合文档解析、用户模拟、风险评估、运营分析的发现。
- 按严重程度和问题类型分类整理所有问题。
- 给出总体结论（通过 / 有条件通过 / 不通过）。
- 提供清晰的决策选项，便于人类快速审阅和确认。

---

## 2. 输入

| 来源 | 说明 |
|---|---|
| 阶段1输出 | 文档解析结果 + 产品认知模型 |
| 阶段2输出 | 用户模拟记录 + 体验问题清单 |
| 阶段3输出 | 风险评估矩阵 |
| 阶段4输出 | 运营分析报告 |

---

## 3. 报告结构

写入 `Base/10-QA验证/QA-xxx-功能名称验证/QA报告.md`。

### 3.1 报告头部

```
# QA 验证报告

- 关联需求：RQ-xxx
- 关联设计：PD-xxx
- 关联方案：TD-xxx
- 关联功能：FT-xxx
- 验证日期：<日期>
- 验证范围：<本次 QA 覆盖的对象包和功能清单>
```

### 3.2 总体结论（放在最前面）

```
## 总体结论

判定结果：<通过 / 有条件通过 / 不通过>

核心发现摘要：
1. <最重要的问题或正面评价，用一句话描述>
2. ...
3. ...

必须修复项：<数量>
建议优化项：<数量>
信息提示项：<数量>

推荐决策：<进入 IMP / 修改后重审 / 否决方案>
```

### 3.3 各阶段发现汇总

#### 文档解析问题（阶段1）
- 链路完整性结论
- 不一致项清单

#### 用户体验问题（阶段2）
按严重程度分组：
- 🔴 阻塞性问题
- 🟡 重要问题
- 🟢 轻微问题

#### 技术风险（阶段3）
引用风险评估矩阵的关键发现：
- 🔴 必须修复的风险
- 🟡 建议关注的风险

#### 运营分析结论（阶段4）
- ROI 评估结果
- 竞争力判断
- 商业风险提示

### 3.4 问题汇总清单

将所有"必须修复"项集中列出，便于人类快速决策：

```
## 必须修复项汇总

| # | 来源阶段 | 问题描述 | 推荐修复方向 |
|---|---|---|---|
| 1 | <阶段> | <描述> | <建议> |
| ... | ... | ... | ... |
```

### 3.5 决策选项（基于风险分级）

为人类提供明确的选择题。根据整体风险等级调整措辞：

```
## 需要人类确认

当前风险评估等级：<🔴 Critical / 🟠 High / 🟡 Medium / 🟢 Low>

请从以下选项中做出选择：

A. **确认通过** — 接受当前方案，允许进入 IMP（实现管理）
B. **要求修改** — 退回 PM Agent，修正所有"必须修复"项后重新 QA
C. **否决该方案** — 暂停该功能开发
D. **部分接受** — 指定哪些必须改、哪些可忽略

你的选择：
```

分级行为规则：

| 风险等级 | AI 行为 |
|---|---|
| 🔴 Critical / 🟠 High | 等待人类明确选择 A/B/C/D，不得自动推进 |
| 🟡 Medium | 给出推荐决策（如"推荐 A"），列出问题清单供抽查；若人类无反对意见可视为通过 |
| 🟢 Low | 标注"低风险、建议直接推进"，记录即可 |

---

## 4. 报告质量要求

- **可读性优先**：人类只需 2-3 分钟就能理解核心结论和关键问题。
- **不堆砌细节**：详细分析放入各阶段子文档，主报告只保留精华。
- **语言简洁**：避免技术术语堆砌；面向非技术决策者。
- **可追溯**：每个问题标注来源（哪个阶段、关联哪个 Base 对象包）。
