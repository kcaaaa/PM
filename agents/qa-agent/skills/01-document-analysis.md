# 阶段1 · 文档解析技能

> 全面理解 RQ / VR / PD / TD / FT 文档，构建完整的产品认知模型。这是后续所有验证的基础。

---

## 1. 职责

- 读取并关联所有相关 Base 对象包（RQ/PD/TD/FT）。
- 提取需求意图、功能边界、技术方案、验收标准的核心要素。
- 检查文档链路完整性，识别缺失或矛盾之处。
- 构建结构化的"产品认知模型"供后续阶段使用。

---

## 2. 输入

| 来源 | 说明 |
|---|---|
| RQ-* | 需求说明、AI候选方案、人类确认记录 |
| VR-* | 需求验证文档（如存在） |
| PD-* | 页面流程、用户路径、交互规则 |
| TD-* | 技术方案、接口设计、数据结构、安全策略 |
| FT-* | 功能说明、功能边界、异常场景、验收标准 |

---

## 3. 执行步骤

### 3.1 链路完整性检查

验证以下追溯链是否完整：

```
RQ（需求） → VR（验证） → PD（产品设计） → TD（技术方案） → FT（功能定义+验收标准）
```

| 检查项 | 通过条件 | 不通过处理 |
|---|---|---|
| RQ 存在且已确认 | 有 `AI候选方案.md` + `人类确认记录.md` | 标记为阻塞问题，退回 PM Agent |
| PD 与 RQ 一致 | 产品设计覆盖 RQ 核心需求 | 标记不一致项 |
| TD 与 PD 一致 | 技术方案支撑产品设计方案 | 标记不一致项 |
| FT 有验收标准 | `FT-*/验收标准.md` 存在且可执行 | 退回 PM Agent 补充 |

### 3.2 内容提取

从各对象包中提取以下核心要素：

**需求层（RQ）**
- 产品目标（一句话）
- 用户痛点 / 业务问题
- 成功标准
- **禁止事项/约束条件**：明确"不能做什么"或"必须遵守的限制"（参考 ASDLC：Agent 必须不能做什么与应该做什么同等重要）

**设计层（PD）**
- 核心用户路径
- 页面结构和关键交互
- 信息架构合理性
- **体验约束**：是否有明确的不可接受行为定义（如"不得让用户等待超过 X 秒"）？

**技术层（TD）**
- 核心技术选型
- 数据模型概要
- 接口边界
- 安全策略
- **技术约束**：性能上限、兼容性要求、禁止使用的技术/模式

**功能层（FT）**
- 功能清单
- 功能边界（做什么 / 不做什么）
- 验收标准（可验证的条件）
- **业务规则约束**：不可违反的业务逻辑或合规红线

### 3.2.1 禁止事项/约束条件检查

> 参考：InfoQ Agentic Development Playbook。高质量的需求文档不仅定义"要做什么"，还必须明确"不能做什么"和"必须遵守的限制"。

对每个对象包执行以下检查：

| 检查项 | 说明 |
|---|---|
| 是否有明确的 Out-of-Scope？ | 需求是否清晰定义了不做的范围？模糊的边界是后期变更的主要来源 |
| 是否有不可违反的业务规则？ | 如"金额超过 X 必须人工审批""不得自动删除用户数据"等 |
| 是否有合规/安全红线？ | 如"PII 数据不得明文存储""外部 API 调用需脱敏" |
| 约束条件是否可验证？ | "不能太慢"是无效约束；"P95 < 2s"是可验证约束 |

如果缺少关键禁止事项或约束条件，标记为"重要问题"并建议 PM Agent 补充。

### 3.3 一致性校验

交叉比对各层级文档，识别以下问题：

| 类型 | 示例 |
|---|---|
| RQ vs PD | 需求说要支持多语言，设计只做了中文 |
| PD vs TD | 设计要求实时协作，技术方案无 WebSocket/长连接 |
| TD vs FT | 技术选型不支持功能定义中的某个核心能力 |
| FT vs 验收标准 | 验收标准无法验证功能说明中承诺的能力 |

### 3.4 构建产品认知模型

将提取和校验结果整理为结构化摘要，作为后续阶段的共享上下文：

```
## 产品认知模型

- 产品名称/模块：<名称>
- 核心目标：<一句话描述>
- 目标用户：<主要用户群体>
- 关键功能清单：
  - <功能1>
  - <功能2>
  - ...
- 技术栈概要：<核心技术选型>
- 链路完整性：<完整 / 部分缺失 / 严重缺失>
- 一致性状态：<一致 / 存在冲突（列出）>
```

---

## 4. 输出

写入 `Base/10-QA验证/QA-xxx-功能名称验证/QA报告.md` 的"阶段1：文档解析"部分。

必须包含：
- 链路完整性结论
- 提取的产品认知模型摘要
- 发现的不一致项（如有）
- 是否可进入下一阶段判断
