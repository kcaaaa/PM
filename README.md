# 全流程产品协作系统 · AI 原生 Agent / Skill
# AI-Native Agent Product Collaboration for PMs & Solo Founders
> **版本**：2.0.0  
> **定位**：面向非开发者、产品经理、业务负责人和 AI 编程工具的纯文件型 Agent / Skill 协作系统。项目以 `Base/` 对象包作为唯一项目认知基准，通过 Orchestrator、PM、QA、Dev、Domain 等 Agent 与 BA、Code、DB、UI 等 Skill 协同，覆盖从需求捕获、方案评估、产品设计、技术方案、QA 验证、代码实现到测试验收和变更管理的完整链路。  
> **使用方式**：本项目无需安装依赖、无需 CLI、无需运行服务。AI 编程工具直接读取 `SKILL.md`、`agents/`、`skills/`、`protocols/` 和 `docs/` 中的 Markdown 规则即可工作。

## 一句话说明

人类只需描述业务想法、问题现象和期望效果；AI 负责识别意图、生成候选方案、维护 `Base/` 对象包、调度 Agent / Skill、定位代码工程文件、执行实现与验证，并把过程记录为可追溯的产品链路。

## 核心理念

- **Base 为唯一基准**：`Base/` 是 AI 的项目认知数据库，所有需求、验证、设计、方案、功能、QA、实现、测试、反馈和变更都以独立对象包管理。
- **候选方案优先**：新需求、新功能、设计取舍、变更和实现策略必须先输出 3-5 个候选方案并推荐当前最优方案，由人类选择、修正或否定。
- **QA 前置验证**：`FT-*` 功能定义确认后，必须经过 `QA Agent` 的用户模拟、风险评估、运营分析和报告确认，才允许进入 `IMP-*` 实现阶段。
- **链路可追溯**：任何代码修改都必须能追溯到 `RQ → VR → PD → TD → FT → QA → IMP → TEST`，变更必须进入 `FB / CR` 链路。
- **非开发者友好**：默认使用者不需要懂代码、路径或技术细节；AI 自行扫描 Base、定位代码目录、解释影响、完成验证并回写记录。

## 快速开始

1. 将本项目复制或克隆到工作目录。
2. 在 Trae、Cursor、Continue、Codex 等 AI 编程工具中打开项目根目录。
3. 让 AI 读取根目录 [SKILL.md](./SKILL.md)，再按任务需要读取对应 Agent / Skill 文件。
4. 用自然语言描述业务想法、功能变化、问题现象或期望效果。
5. AI 按候选方案、Base 对象包、QA 验证、实现和测试验收链路推进。

无需 Node.js、npm、Python 环境、数据库或任何命令行工具。

## 系统架构

### Agent 角色

| Agent | 职责 |
|---|---|
| Orchestrator | 识别真实意图、扫描 Base、生成候选方案、推荐最优路径、调度后续 Agent |
| PM Agent | 维护 `RQ → VR → PD → TD → FT → QA → IMP → TEST → FB → CR` 产品链路与关键闸口 |
| QA Agent | 在实现前进行文档解析、用户模拟、风险评估、运营分析和 QA 报告输出 |
| Dev Agent | 在 QA 通过后，基于 `IMP-*` 实现包执行代码任务并记录验证结果 |
| Domain Agent | 提供数据库、SQL、UI/UX、技术方案和性能等专业判断 |

### Skill 能力库

| Skill | 用途 |
|---|---|
| BA Skill | 业务分析、隐性需求挖掘、访谈问卷、需求方案生成，复杂场景可结合 Council Advisor |
| PM Skill | 产品流程调度、Base 对象包管理、模板与闸口控制 |
| Code Skill | 编码行为规范索引，覆盖工具使用、任务管理、验证、调试、性能、API、CI/CD、架构等 21 个子技能 |
| DB Skill | 数据库建模、命名规范、SQL 模板、性能调优和案例模板 |
| UI Skill | UI/UX 工作流、设计系统、Web / 多端技术栈、检查清单和知识库 |
| Extension Skills | TypeScript、移动端、系统优化、代码审查、Office 文档梳理（.docx/.xlsx/.pptx 创建、检查、整理）等高级扩展能力 |
| Prompt Skills | 阶段提示词与关键节点提示词，用于统一多阶段协作表达 |

## Base 工作方式

```text
人类输入方向
→ AI 识别意图与当前 Base 状态
→ AI 生成 3-5 个候选方案
→ AI 推荐当前最优方案
→ 人类选择 / 修正 / 否定
→ AI 写入 Base 对象包
→ PM 推进 RQ → VR → PD → TD → FT
→ QA Agent 执行强制验证
→ QA 通过后创建 IMP 并进入 Dev 实现
→ TEST 测试验收
→ FB 反馈 / CR 变更 / 回归测试
```

## Base 与代码工程目录关系

`Base/` 不存放真实源码。真实代码、配置、脚本和测试应放在与 `Base/` 平级的代码工程目录中，例如 `apps/`、`services/`、`packages/`、`infra/`、`scripts/`、`tests/` 或具体技术栈约定目录。

`Base/06-实现管理/IMP-*` 是 Base 与代码之间的桥梁，只记录要修改哪些工程文件、为什么修改、如何验证、如何回滚；真实源码由 AI 写入代码工程目录。

## 主要使用场景

- 从零启动新产品或新项目，初始化 Base 项目认知数据库。
- 将模糊想法转化为候选方案、需求对象包和产品链路。
- 设计页面流程、用户路径、交互规则和技术方案。
- 在功能实现前执行 QA 验证，提前发现逻辑、体验、技术、运营风险。
- 基于已确认 `IMP-*` 执行代码实现、Bug 修复、测试和验收。
- 处理反馈、偏差、需求变更和回归测试。
- 提供数据库、UI、架构、API、CI/CD、性能、安全等专业咨询。

## 维护原则

- 顶层入口只保留调度规则，不堆叠下级方法论。
- 新增产品阶段时，优先新增 Base 对象包类型或对象内文档。
- 新增领域能力时，优先新增 Skill 或 Agent 文件，并同步更新入口、场景介绍和 README。
- 所有文档必须与 `SKILL.md`、`agents/`、`skills/`、`protocols/` 的当前结构保持一致。
